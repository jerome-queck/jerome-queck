# Public data graphics

The data core remains useful after the owner rejected the initial field-journal profile composition. This file records the data and rendering choices; it does not approve that rejected composition.

Merge cadence and the calendar start on 1 July 2026 and end at the collection date. The current month is partial. Weekday frequency groups the same UTC calendar records. All-time authored-public-PR and linked-closed-issue counters retain their original scope.

"Open-source contributions" counts public PRs authored by `jerome-queck` outside repositories owned by `jerome-queck` or `Jerome-Group`. This is a complete scoped search, not the retained two-event sample or just the featured fixes. Its merged and open counts are separate. Repositories with PRs include any state. Closed without merge remains distinct in repository status. An open PR's merge-commit field does not establish a merge. The collector fails on more than 1000 results, count changes, duplicate records, incomplete pages or nonadvancing cursors.

Schema 4 requires full upstream PR records, language-byte maps and physical source-line counts at the nine selected public repository commits. Missing or incomplete fields fail; valid empty fields remain empty. The main world shows the ten largest cloc language classifications by physical code lines, plus Other. This includes JSON, text, markup and configuration across all authors. Comments, blanks, files, remaining languages, excluded directories, tool checksum and exact source commits stay in the native snapshot. See [source-line method and limitations](../research/source-lines.md). No byte-to-line conversion is used.

The older individual repository-pulse graphics retain separately labelled GitHub language bytes. GitHub language connections must fit the 100-language request and match their reported totals. These classifications may differ from cloc and can include generated or vendored contents. Neither metric measures expertise, personal authorship or time.

Fraunces 600, Source Sans 3 regular and IBM Plex Mono regular use local OFL sources pinned by commit and SHA256 in `assets/type/manifest.json`. That manifest also records axes and license hashes. `scripts/profile_style.py` owns palette, font roles, HarfBuzz shaping, measured ink and advances, missing-glyph failure and local outline reuse. Renderers own their composition. The engine is uharfbuzz 0.43.0 with HarfBuzz 10.1.0 and fontTools 4.55.3. No image font loads at runtime. Arbitrary Unicode titles and exact release tags stay complete in the native snapshot. Glyph zero and overflow fail the refresh instead of producing tofu or clipped text.

The fifteen required publication names include four continuous world SVGs; the Git publication block copies and stages all four alongside the nine individual SVGs and two native snapshot files. Every required source and all rendering finish before output writes. A new source or rendering failure retains the previous complete publication and timestamp. Native snapshot Markdown includes exact values, states, timestamps, source links and definitions. SVG titles and outlined text labels retain descriptive alternatives. GitHub controls native Markdown's font.

Install `requirements.txt` in a virtual environment. Run `python -m scripts.profile_data /absolute/output/directory` with authenticated `gh`. For a saved schema-4 snapshot, call `render_snapshot` to regenerate the same fifteen payloads. Do not commit live output to the source branch. Run `python -m unittest discover -s tests`, `ruff format --check scripts tests formal` and `ruff check scripts tests formal`. The [schema-3 metric definitions](../research/data-metrics-v3.md) cover contribution kinds, merged patch footprint and completed-day proposal ages.
