name: profile-publication
description: Check complete, failure-retaining profile-data publication after changes to collection, rendering, workflow publication, or its tests.
---

A partial refresh can show contradictory public facts. The checked promise is that an existing profile-data ref contains one complete generation after a successful push; failure before push leaves the ref untouched, and a stale non-force push cannot overwrite a newer commit.

Run `python3 formal/check.py`. It verifies source hashes, runs the real workflow's bare-Git publication fixture, deletes one copy in a scratch workflow and requires a mixed-snapshot failure, then runs TLC 2.19 (TLA+ tools release v1.7.4, revision 5a47802) and its corresponding missing-copy mutant. Java is required. Set `JAVA` to its executable and optionally `TLA2TOOLS` to the SHA-256-pinned jar; otherwise the checker downloads the pinned release into the user cache. Read each TLA+ result with `/statechart` for the shortest broken path or a chart. The source hash check is a drift alarm, not evidence of semantic equivalence.

Coverage is `.github/workflows/profile.yml` generate and publish jobs, `scripts/profile_data.py` `collect_snapshot`, `render_snapshot`, `main`, and `tests/test_publication.py` fixture and `tests/test_formal_publication.py` stale-push fixture. Last confirmed source base: `92b883461dbd1031a74d0730f40f83c891e6ce8b`. The model maps collect/render success to Ready, each ordered copy to Copy, abort to Fail, and Git's atomic non-force ref update to Push. Copy 6 is the missing-copy mutant. The fixture executes the extracted shell against a real bare Git repository, including every missing file and a full snapshot. The modeled ref starts with a complete existing snapshot. Two publishers attempt once each; interleavings are adversarial even though workflow concurrency serializes hosted runs. Every generation has exactly 11 files. Collection, rendering, artifact transfer and each copy may fail; the model abstracts all pre-push failures as Fail. Git atomically checks ancestry and advances the ref; no force push or other writer is assumed. Equality of the tracked generation represents ancestry in this two-attempt bound.

The check does not prove the internals of the individual data fetchers or renderers, GitHub API truth, font layout, scheduler behavior, cache visibility, first publication, or arbitrary writers. It does not execute the hosted runner. Snapshot generation and artifact upload are assumed to succeed before Ready; the tests establish missing payload failure for the existing-ref case. Model checking explores a bounded abstraction, not Python or shell semantics. Source hashes force review of changes but cannot prove that the mapping was correct.

On drift, read the diff from the sync commit, including moved writers and workflow callers. Decide whether it changes an atomic boundary, failure path, payload list or promise. Update the model and fixture from actual code, never weaken the property to obtain a pass. Replay any counterexample against the real workflow: an impossible step means model drift; a reproducible sequence means a code bug. Run the command, verify both mutants fail for their stated reason and the original passes, then update source hashes and the sync commit only after confirming the new mapping. For accumulated changes use `/maintain-formal-verification-skill`. Run this manually whenever covered code changes; the repository CI invokes the check as well.
